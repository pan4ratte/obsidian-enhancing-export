Экспортируйте заметки с помощью Pandoc, не притрагиваясь к командной строке: любая опция, которую предлагает Pandoc, доступна прямо в интерфейсе Obsidian. Создавайте шаблоны экспорта для Word, PDF, LaTeX, HTML, EPUB и многих других форматов, а также устанавливайте дополнительные lua-фильтры прямо из магазина в плагине.


## Фичи

### 1. Все функции Pandoc в графическом интерфейсе

Гибкий редактор шаблонов позволяет настраивать экспорт заметок, не используя командную строку. Настроить можно всё: оглавление, его глубину, нумерацию разделов, движок PDF, подсветку синтаксиса, отрисовку формул, размер бумаги и шрифтов, расположение сносок и многое другое.

### 2. Десятки форматов экспорта

Word, OpenOffice, PDF, LaTeX (целый документ или фрагмент для вставки в существующий проект), HTML, EPUB, слайды Beamer и reveal.js, PowerPoint, Markdown в вариантах CommonMark, GFM или Hugo, Typst, TextBundle, RTF, MediaWiki, reStructuredText, Textile, OPML, простой текст и библиография BibTeX из всего, что процитировано в заметке.

### 3. Экспорт с учётом синтаксиса Obsidian

Плагин учитывает и исправляет многие проблемы как самого Pandoc, так и других плагинов для экспорта из Obsidan. Например, полностью работает встраивание `![[заметок]]` и `![[разделов#заметок]]`. `==Выделения==` сохраняются, блоки `$$…$$` встраиваются, а каждое `$today` в заметке становится сегодняшней датой. Расширенные настройки и твики позволяют включить обработку дополнительного синтаксиса — выносок, кодов эмодзи, голых URL, жёстких переносов строк и не только.

### 4. Магазин lua-фильтров

Lua-фильтр — это небольшой скрипт, который Pandoc применяет к документу при экспорте, что позволяет ещё более тонко настроить документ: добавить разрывы страниц в Word, диаграммы из блоков кода Mermaid, вложенные заметки, химические формулы или партитуру с нотами. Магазин фильтров предлагает более трёх десятков фильтров, сгруппированных по задачам, которые они решают с указаний требований к их использованию.

### 5. Pandoc под присмотром

Ваш Pandoc всегда будет актуальной версии, потому что плагин отслеживает обновления и предлагает их установить, если обнаружена новая версия. Также, прямо из плагина можно открыть руководство пользователя и список изменений.


## Установка

### Прежде всего установите Pandoc

1. Плагин управляет Pandoc, но для этого его нужно сначала установить с официального сайта: [https://pandoc.org/installing.html](https://pandoc.org/installing.html).

2. Затем либо добавьте его в `PATH` своей системы, либо укажите путь к установленной программе вручную в настройках плагина.

3. Для экспорта напрямую в PDF дополнительно нужен дистрибутив LaTeX — MiKTeX, TeX Live, рекомендуемый мной [TinyTeX](https://github.com/rstudio/tinytex-releases) или любой другой движок, который поддерживает Pandoc.

### Способ 1: магазин плагинов Obsidian

1. В настройках Obsidian откройте вкладку «Сторонние плагины» и нажмите кнопку «Обзор».

2. В строке поиска введите `Pandoc GUI`, нажмите на результат, затем кнопки «Установить» и «Включить».

Кроме того, плагин можно установить по ссылке на сайт сообщества: [https://community.obsidian.md/plugins/pandoc-gui](https://community.obsidian.md/plugins/pandoc-gui)

### Способ 2: плагин BRAT

Если вы хотите протестировать бета-версии плагина или использовать предыдущие версии, это можно сделать с помощью плагина `BRAT`:

1. Установите плагин `BRAT` из официального магазина плагинов Obsidian.

2. В настройках `BRAT` найдите раздел «Beta plugin list» и нажмите кнопку «Add beta plugin».

3. В появившемся окне вставьте ссылку на репозиторий плагина `Pandoc GUI`: [https://github.com/pan4ratte/obsidian-pandoc-gui](https://github.com/pan4ratte/obsidian-pandoc-gui)

4. В поле «Select a version» выберите нужную версию и нажмите кнопку «Add plugin». Плагин установится автоматически и будет готов к работе.

## Свои команды экспорта

Выберите `Custom` при создании шаблона экспорта и напишите любую команду — вызов Pandoc, который не покрывают строки настроек, или вообще другую программу. Переменные ниже подставляются перед запуском.

## Переменные

В своей команде экспорта можно использовать `${переменные}`, их значения:

| Ключ                      | Значение                                                     |
| ------------------------- | ------------------------------------------------------------ |
| `${outputPath}`           | Полный путь экспортированного файла. При экспорте в `/User/aaa/Documents/test.pdf` это он целиком. |
| `${outputDir}`            | Папка, в которую сохраняется экспортированный файл, — `/User/aaa/Documents` в примере выше. |
| `${outputFileName}`       | Имя экспортированного файла без расширения — `test` выше. |
| `${outputFileFullName}`   | Имя экспортированного файла с расширением — `test.pdf` выше. |
| `${currentPath}`          | Путь экспортируемой заметки. При редактировании `/User/aaa/Documents/readme.md` это он целиком. |
| `${currentDir}`           | Папка экспортируемой заметки — `/User/aaa/Documents` выше. |
| `${currentFileName}`      | Имя заметки без расширения — `readme` выше. |
| `${currentFileFullName}`  | Имя заметки с расширением — `readme.md` выше. |
| `${vaultDir}`             | Папка самого хранилища. |
| `${attachmentFolderPath}` | `attachmentFolderPath` из настроек Obsidian. |
| `${pluginDir}`            | Папка этого плагина, для ресурсов, которые он поставляет. |
| `${luaDir}`               | Папка `lua/` плагина, куда записываются установленные фильтры, — то, что называет `--lua-filter`. |
| `${embedDirs}`            | Папки файлов, которые вкладывает заметка, для `--resource-path`. |
| Другие переменные         | Напишите `keyword: value` в [YAML front matter](https://jekyllrb.com/docs/front-matter/) заметки и используйте как `${metadata.keyword}`. |

### Что можно писать внутри `${...}`

Кроме имени переменной внутри `${...}` допускается небольшой набор выражений — его хватает, чтобы опция появлялась в команде только тогда, когда она нужна:

| Запись | Что делает |
| ------ | ---------- |
| `${metadata.keyword}`, `${today.iso}` | Обращение к полю; `${options["ключ"]}` — то же самое в скобках. |
| `` ${ x ? `--opt="${x}"` : `` } `` | Условие. Вложенные шаблонные строки в ветках работают. |
| `${x ?? "по умолчанию"}`, `${x \|\| "запасное"}`, `${x && "…"}`, `${!x}` | Значение по умолчанию и логические операции. |
| `${fmt === "pdf" ? "…" : "…"}` | Сравнение: `===`, `!==`, `==`, `!=`. |

Имя, которого нет среди переменных, остаётся в команде как есть: `${user}` так и напечатается — так опечатку видно в строке «Результирующая команда».
